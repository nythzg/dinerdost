# Local bill reward details

The receiving user requested the saved loyalty reward name and current billing updates on bills. Web only, local and unreleased.

Newly generated provisional bills and final invoices record a discountBreakdown in the immutable document snapshot. It separates named loyalty claims, coupon codes with their actual reductions, and other/manual discounts. Matching entries are grouped without merging different reward names or coupon codes. Rejected/voided rounds are excluded consistently with bill totals.

Thermal screen and 80mm/PDF rendering use only that issued snapshot. Named loyalty rewards replace the generic Discount label for their amount; coupons display Coupon followed by the recorded public code. Other discounts keep their own Discount row. The existing item quantities/prices, subtotal, named taxes, charges, saved amount, signed round off, grand total, received/outstanding, customer/table, branding and replacement credit continue using recorded values. Financial calculations and defaults are unchanged; no discount is counted twice.

The saved reward name belongs to each actual claim. Changing the outlet default affects subsequent claims; it does not rename an earlier claim or rewrite an issued bill. Reprints remain frozen. Older snapshots without the new metadata retain their original generic Discount line because the issued document did not record the split; neither a current setting nor current order data is substituted. Generate a fresh provisional bill through the existing billing workflow to capture the current order details. Existing final invoices retain their identity and original snapshot.

The service adds descriptive snapshot metadata only for web generation. There is no new endpoint, permission expansion, database migration, backfill, financial/stock mutation or native policy change. Existing bill authorization, tenant/outlet scope, order locks, exact retries and final-invoice deduplication remain.
