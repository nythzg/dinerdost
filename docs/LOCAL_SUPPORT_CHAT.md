# Local support chat

Local, uncommitted web update for the requested restaurant-header support icon. This currently serves restaurant staff contacting Diner Dost. Diner-to-restaurant QR support is a separate audience and has not been assumed or added.

## Use

- Open the headset beside the notification bell and package button. Start a chat for Technical support, Billing & payments, Account & setup, or General support. The selected outlet is recorded with the request.
- Conversations are persisted, private to the requesting employee and authorized platform support staff, and linked to existing support tickets. Messages refresh every five seconds while the panel is open and the page is visible. There is no invented online status or promised response time.
- In Superadmin, open Support & broadcasts. The Shared message desk is first, visible to Superadmin and enabled Support-role/custom-permission members within their existing restaurant scope. Search by restaurant, outlet, requester or subject; filter team, status, My chats and Unassigned. Server pagination reaches every matching conversation, 50 per page. The existing broadcast/evidence/deadline tools remain below the desk.
- Assign a specialist from enabled platform members with support permission and access to that restaurant, or use Take this chat to claim it. Existing platform roles and tenant scopes remain authoritative; choosing a team never grants a permission. Share chat provides a deep link which still requires the recipient's own sign-in, support permission and restaurant scope.
- Reply directly, change routing with a version guard, or mark solved with a message shared with the requester. Superadmin alone may close a chat, with a closing message retained for the customer. Solved/closed chats reject new replies; closed chats stay in searchable history, leave active counts/escalations, and cannot be hidden or moved through the generic ticket editor. Another request can be opened.
- View restaurant / Troubleshoot restaurant opens the exact chat's restaurant, with password and reason, the chat reference in the audit trail and the existing 15-minute session-bound access. Support staff receive read-only access. Only Superadmin may explicitly enable troubleshooting changes; ordinary owner financial, stock, permission and version guards still apply. Exit returns to the same conversation. No device/desktop remote-control capability is implied.
- Global platform support staff can open Support email & WhatsApp settings to save the real address and international phone number. Empty contacts display Not configured. Email opens the user's email application; WhatsApp opens its official click-to-chat URL. No external message is sent by this app, and external replies are not synchronized into the in-app conversation.

## Boundaries

The service revalidates live restaurant sessions before entering the narrow private platform-data bridge. Direct tenant SQL cannot access either new table. Native sessions, disabled/expired sessions, delegated owner views, other requesters and out-of-scope platform staff cannot use the requester endpoint. CSRF, strict input validation, idempotent retries, audited writes and immutable message history are enforced. A conversation cannot be moved to another restaurant through the generic ticket editor. Original financial, stock, invoice and customer records are untouched.

Requester history currently shows the latest 50 cases, with unresolved requests first. The platform desk now paginates every authorized match, removing its earlier 100-case cap. Each requester may have ten open cases; each conversation holds up to 2,000 messages, with 60 sends per user per ten minutes. No attachments, external delivery provider, unread-message push notification, agent-presence indicator or automatic specialist assignment is claimed.

## Browser voice calls

Either participant can request an audio call inside an active conversation. Answer/decline, mute/unmute and hang-up use browser WebRTC audio. Only the actual participants can control an answered call, with Superadmin also allowed to end it; competing answers use version guards. Finishing the case ends its active call. Incoming customer calls are marked in the shared list; incoming support calls mark the customer's header button and open their conversation when selected. Microphone capture starts only after Start/Answer and stops on hang-up, failure, navigation or closing the panel. Keep the chat open during the call.

Private authenticated signalling is stored separately; there is no audio recording or external calling provider. Unanswered rings expire after 90 seconds; answered sessions have a two-hour safety expiry. Calls require a secure browser context (HTTPS or localhost), microphone permission and currently a direct local-network connection. No TURN relay is configured, so reliable internet/NAT calling and physical microphone/device testing are not claimed. This limitation is shown in the UI. See [WebRTC's relay guidance](https://webrtc.org/getting-started/turn-server) and [browser microphone requirements](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
