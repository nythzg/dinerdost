## Completion gate

For any resumed item: inspect all callers, preserve existing guards/history, use isolated synthetic QA, add the smallest meaningful behavior/concurrency/privacy checks, inspect desktop/phone UI, run hosted PostgreSQL where the changed database behavior warrants it, and record precise failures/replays and untested hardware. Update its existing ID only after code/tests AND deployment evidence. Never change Q/PP/V2 counts just because a batch or scaffold was published. No force push, production seed/reset/restore, guessed opening values or external messages.
